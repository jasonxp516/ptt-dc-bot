# PTT-DC-Bot v1.2.0 發行說明

發布日期：2026-11-10

本版為可靠性與權限修正版，依據 `docs/ptt-dc-bot-modification-plan.md` 審查結果實作。
**無資料庫 Schema 變更**，可直接覆蓋升級，亦可安全退回 v1.1.0。

## 升級前須知（行為變更）

- `/admin` 僅限 bot owner（`OWNER_USER_ID` 或自動識別之主伺服器擁有者）。主伺服器內具頻道管理權限的成員不再能執行全系統管理。
- Telegram 群組內的 `/keyword_add`、`/pause`、`/resume` 與刪除按鈕，僅限群組 creator / administrator 或 `TELEGRAM_ADMIN_USER_ID` 名單（逗號分隔）。私訊不受影響。
- 新設定 `MAX_ARTICLE_AGE_HOURS`（預設 `24`）：發文超過此時數的未讀文章視為歷史文章，只標記已讀不推播。

## 漏報與巡檢

- 停機或爆量時沿分頁回補（最多 5 頁，直到已讀文章或超過 24 小時），單輪超過 20 篇改為分輪處理，不再直接丟棄。
- 低流量看板不會在 14 天清理後重推首頁舊文。
- AI 模糊規則判斷失敗（限流 / 逾時）時保留文章下輪重試。
- 多關鍵字順序（`3060 台北` / `台北 3060`）不再影響商品與價格判斷；多品項文章找不到目標品項價格時不再誤用其他商品價格。
- 修正爬蟲優先級閘門於等待者取消時可能永久鎖死。

## AI、看板、售出追蹤

- AI 任務期限自送出起算（互動 30 秒 / 背景 120 秒），涵蓋排隊與所有請求。
- AI 重複加入已追蹤看板不再重建全域基準。
- 暫停中的規則保留看板登記；恢復訂閱時自動補回遺失看板。
- 更換推播頻道後，舊卡片仍於原頻道原位更新。
- 「洽談中 / 暫勿來信」不再永久結案，後續售出或恢復販售都會更新卡片。

## Telegram

- 卡片截斷不再切斷 HTML 實體；格式被拒時改送純文字；單篇失敗不阻斷同批。
- `/keyword_add 3060Ti 台北` 不再把關鍵字誤判為看板；新看板先驗證存在。
- 溢出摘要發送失敗不再被記為已送達；非 JSON 回應會重試。

## 維運

- 每日備份須完整性檢查通過才記為完成，失敗每 30 分鐘重試並保留舊備份。
- 儲存層時間戳與每日維護日界統一為台北時區。
- 發行測試門檻改跑完整 pytest 與售出基準評測；相依套件加上主版本上限。

## 已知限制（延後處理）

- 單一訂閱者推播於平台端持續失敗（如頻道被刪）時，該篇仍不會補送（計畫 F01，需持久投遞佇列）。
- 新訂閱建立前後約一個巡檢間隔內的文章可能多推或少推一篇（F14）。
- 看板抓取恢復後尚無「已恢復」通知（F06）；停用 Discord 單獨運行 Telegram/Email 尚未支援（F10）。
