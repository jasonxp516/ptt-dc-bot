PTT 智慧二手交易追蹤與多平台即時推播機器人
PTT-DC-Bot: An Intelligent PTT Marketplace Monitoring and Multi-Platform Notification System

專題類別：分散式網路爬蟲、自然語言處理 (LLM)、非同步微服務、多平台通訊系統
版本狀態：v1.1.0 (Official Production Release)
開發環境：Python 3.10+ / SQLite 3.35+ (WAL) / Docker Multi-Arch (GHCR)
開源授權：MIT License (100% 離線可測、零付費 API 成本)
專案核心摘要：
PTT-DC-Bot 為解決台灣最大網路二手交易板塊（HardwareSale、MacShop 等）資訊不對稱與傳統爬蟲無效推播痛點而設計。系統結合純函式狀態機、簽名檔穿透推文判定與 Groq 免費三模型動態輪替調度池（24,000 TPM），創新實現「18 小時已售出原位劃線更新」、「合售多品項虛擬獨立視角切分」、「硬體型號與預算消歧義」及「Crawl-Once, Fan-Out 高效全域共享快取」。系統一次整合 Discord、Telegram 與 Email 三大通訊協定，並以 SQLite WAL 支援公用頻道與個人私訊多租戶隔離，經 250 項單元測試與 80 筆真實樣本評測驗證，達到 100% 售出判定準確率。

1. 研究背景與動機 (Background & Motivation)

在台灣的二手電腦硬體與 3C 消費市場中，PTT（批踢踢實業坊）擁有極高的公信力與交易量。然而，優質或高性價比商品往往在上架數分鐘內即遭搶購。現存開源推播工具普遍存在以下嚴重缺陷：

  • 過時無效通知（Dead Notifications）：賣家常於內文或推文標註「已售出」，但傳統機器人缺乏追蹤能力，買家點入才發現白跑一趟。
  • 多品項合售文誤判（Multi-Item Collision）：一篇貼文常合售數項商品（例如：「1060已售/3060Ti」），傳統爬蟲一見「已售」即全篇略過，導致真正欲購買 3060Ti 的使用者錯失通知。
  • 規格型號誤判為售價（Model-Price Confusion）：硬體型號（如 RTX 3060、12G、750W）經常被正則表達式誤擷取為標價，導致價格上限過濾機制崩潰。
  • 社群廣播與個人隱私衝突：現有工具缺乏完善的多租戶隔離，無法在同一實例下兼顧「伺服器公用通知」與「個人私密 DM 追蹤」。

2. 專案目標與核心創新 (Objectives & Core Innovations)

1. 純函式售出狀態機與 18h 原位更新 (In-Place Edit)：
建立獨立狀態機（sold_rules.py），有效過濾地名（如「可洽中壢站」）與時間偽陽性；穿透抓取作者簽名檔後最新推文，於售出時直接編輯 Discord/Telegram 原始卡片劃上刪除線，不重複洗版。
2. 多品項虛擬視角切分 (Per-Keyword Virtual Slicing)：
開發 apply_keyword_view 演算法，將合售文章依不同關鍵字切出獨立視角，分別計算各別品項價格與售出狀態。
3. Crawl-Once, Fan-Out 高效爬取與優先級調度：
每個看板每輪僅抓取一次，全域共享文章與 AI 判定快取；透過 P0～P3 優先級佇列與冷卻機制，徹底避免高頻請求引發 PTT 503 阻擋。
4. Groq 三模型動態輪替池與 Prompt Injection 縱深防禦：
輪替調度 3 組免費開源模型，將免費額度擴充至 3 倍（24,000 TPM）；PTT 非信任文字一律以 wrap_untrusted 轉義，並透過 Intent Guard 意圖鎖定機制保護後端寫入工具。

8. 預期效益與專案總結 (Expected Impact & Conclusion)

實用與社會效益：為二手 3C 交易社群提供首個開箱即用、零伺服器維護負擔且絕不洗版的智慧監控工具。透過原位劃線更新機制，大幅減少買賣雙方的無效溝通成本，有效促進二手商品流通與電子產品循環經濟。
學術與工程價值：本專案展示了現代 Python 非同步架構的工程實踐，成功將傳統正則比對、狀態機理論與大型語言模型（LLM）進行分層融合。透過精細的快取調度、微服務解耦與縱深防禦機制，為社群爬蟲與即時通訊機器人開發樹立了高可靠度與標準化之範例。
